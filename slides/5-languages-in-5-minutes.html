Javascript

Backpropagation as a method on Value

  backward() {
    const topo = [];
    function buildTopo(node) { ... }

    buildTopo(this);
    this.grad = 1;

    for (let i = topo.length - 1; i >= 0; i--) {
      const node = topo[i];
      const v_grad = node.grad;

      node.children.forEach((child, index) => {
        child.grad =
            (child.grad || 0) + v_grad * node.grads[index];
      });
    }
  }

Haskell (1st try)

Value is a data structure

data Value = Value
  { tag :: Int
  , value :: IORef Double
  , grad :: IORef Double
  , children :: [Value]
  , gradients :: [Double]
  }

“Polymorphic” functions for binary/unary operations

op2 f da db l@(Value _ a g _ _) r@(Value _ b g' _ _) =
 unsafePerformIO $ do
    a' <- readIORef a
    b' <- readIORef b
    v <- newIORef (f a' b')
    g <- newIORef 0
    t <- nextTag
    pure $ Value t v g [l, r] [da a' b', db a' b']
  • use a lot of “side-effects”
  • very ugly and non-idiomatic Haskell!
  • very slow

Forth

Computation nodes are structures

begin-structure node
  field: node-op    \ the type of the operation
  field: node-val   \ the value of this node
  field: node-w1    \ derivative function (xt): ( p1 p2 -- ; -- f ) applied to children
  field: node-w2
  field: node-p1    \ parent positions; -1 for leaf nodes (constants/variables)
  field: node-p2
  field: node-grad  \ accumulated gradient, initialised to 0e
end-structure

All nodes are laidout on a Wengert tape

\ a potentially growable structure holding the derivatives of operations
\ on dvals
begin-structure tape
  field: tape-size   \ available position
  field: tape-max    \ number of available nodes
  field: tape-nodes  \ vector of nodes
end-structure
  • key insight about efficient reverse AD technique based on tape or list
  • computation nodes reference previous nodes and store functions to compute derivative
  • pandoc does not even have syntaz highlighting for Forth

Forth

  • 😓 Very low level, requires careful baby-step to maintain stack discipline
    • 30% manual coding/testing, 70% written by Claude
    • No types ⇒ easy to introduce subtle bugs
    • ≅ assembly language
  • 💡 Manipulating the “tape” directly helped a lot to understand the technique
    • Fits nicely stack-based memory allocation
  • 😌 Somewhat “zen” to code with few primitives and concepts

Haskell (2nd try)

Express the whole logic as a Program

data Program = Program
  { pBinds :: V.Vector Bind
  , pOutput :: BindId
  , pAuxOutputs :: [BindId]
  , pNumParams :: Int
  }
  • key insight: distinguish the construction of the (forward) expression graph from evaluation
  • Can interpret a progrem over a Tape, Delta or Graph construction

Expressions are completely symbolic using so-called De Bruijn indices for reference

data Bind
  = SConst Double
  | SAdd BindId BindId
  ...
  | SSum BindId           -- sum(vec) -> scalar
  ...
  | VConst [Double]       -- constant vector
  ...
  | VLinear BindId BindId -- linear(vec, mat_param) -> vec
  | VSoftmax BindId
  | VRMSNorm BindId

Decouple expression from interpretation

-- Tape-based interpretation
interpretProgram :: Program -> TapeM s TNode
...

-- Delta-based interpretation
interpretProgram :: UV.Vector Double -> Program -> DeltaM DNode
...

-- Graph generation
programToDot :: Layout -> Program -> String

Idris

Use the types, Luke!

data Ty = V (List Nat)

||| Aliases for common shapes.
public export Scalar : Ty; Scalar = V []
public export Vec : Nat -> Ty; Vec n = V [n]
public export Mat : Nat -> Nat -> Ty; Mat r c = V [r, c]

Well-typed and well-scoped expressions

data Expr : Ctx -> Ty -> Type where
  -- Variables and constants
  Var     : Elem ty ctx -> Expr ctx ty
  ...
  -- Element-wise operations (uniform over any shape)
  Add     : {dims : List Nat} -> Expr ctx (V dims) -> Expr ctx (V dims) -> Expr ctx (V dims)
  ...
  -- Scalar-tensor broadcast
  Scale   : {dims : List Nat} -> Expr ctx Scalar -> Expr ctx (V dims) -> Expr ctx (V dims)
  -- ML-specific ops
  Linear  : (rows, cols : Nat) -> Expr ctx (Vec cols) -> Expr ctx (Mat rows cols) -> Expr ctx (Vec rows)
  ...
  -- Let binding
  Let     : (ty1 : Ty) -> Expr ctx ty1 -> Expr (Snoc ctx ty1) ty2 -> Expr ctx ty2

Idris

  • Mostly coded by Claude

Sapir-Whorf Hypothesis

  • languages shape our thought
  • come in weak and strong form
  • heavily debated, with few empirical but somewhat minor confirmations
  • nevertheless feels somewhat intuitively “true”: it’s hard to think outside of a language
  • when it comes to PL, it’s probably quite true because of the constrained nature of PL syntax and semantics
  • => interesting to try approaching a problem from different languages angles

Thinking with Simondon

  • The technical object is an integral part of human culture
  • It is actually a mediator between humans and the world
  • Failing to think, understand and tame it leads into alienation

“Les idolâtres de la la machine présentent en général le degré de perfection d’une machine comme proportionnel au degé d’automatisme, or une machine purement automatique, complètement fermée sur elle même dans un fonctionnement pré-déterminé, ne pourrait que donner des résultats sommaires. La machine douée d’une haute technicité est une machine ouverte, et l’ensemble des machines ouvertes suppose l’homme comme organisateur permanent, comme interprète vivant des machines les unes par rapport aux autres. Loin d’être le surveillant d’une troupe d’esclave, l’homme est l’organisatuer permanent d’une société d’objets techniques qui ont besoin de lui, comme les musiciens ont besoin du chef d’orchestre.”

  • individualisation de la machine est une asymptote, une analogie avec le vivant qui est individué dès sa naissance tandis que la machine tend vers l’individuation mais n’y parvient jamais
  • processus de concrétion (intégration dans un milieu) toujours en cours, jamais complètement réalisé

Pharmakon

  • An old concept from Ancient Greece, a religious sacrifice or scape goat
  • Plato uses it to designate alternatively and ambiguously philosophy and sophism
  • Philosophy, and dialog, are a cure
  • Sophism, and writing, are a poison

Pharmakon

  • Reused by Derrida and then Bernard Stiegler
  • Any technology is a pharmakon and therefore inherently ambiguous
  • ⟿ We must seek the cure in the poison
